# 2025-11-20の学習記録

## 今日学んだこと

### 1. 読書メモ用のテンプレートと著作権チェックの仕組み

TILリポジトリで読書メモを管理するにあたり、著作権に配慮したテンプレートとチェック機能を実装した。

**実装内容:**

1. **`Books/読書メモテンプレート.md` の作成**
   - 書籍情報（タイトル、著者、出版社、リンク）
   - 学び・気づき、ネクストアクション、感想のセクション
   - 各セクションにHTMLコメントで著作権に関する注意書きを埋め込み
   - 「本文の丸写し禁止」「引用は出典明記」「写真貼らない」などを記載

2. **`/check-book-notes` カスタムコマンドの作成**
   - Books/ ディレクトリ内の変更ファイルを自動検出
   - git diff で差分を取得し、以下の観点で審査：
     - 丸写しチェック（5行以上の長文転記）
     - 引用の適正化（引用記号と出典の確認）
     - 画像の確認（書籍の写真の有無）
     - 独自性（自分の感想や試したことの有無）
   - 問題があれば具体的な修正ポイントを指摘

**ポイント:**
Public リポジトリで読書メモを管理する際は、著作権侵害を避けるため、必ず自分の言葉で再構築することが重要。

### 2. TILリポジトリの運用ドキュメント整備

3日間の運用で追加された機能を反映し、CLAUDE.md と CONTRIBUTING.md を更新した。

**更新内容:**

1. **CLAUDE.md に追加**
   - リポジトリ構成に `Draft/` ディレクトリを追加
   - テンプレートファイルのセクション（Diary/Books/Draft/）
   - 著作権ガイドライン（Books/ 専用）
   - カスタムコマンドのセクション（`/daily-summary`, `/create-pr`, `/check-book-notes`）

2. **CONTRIBUTING.md に追加**
   - カスタムコマンドを使った効率的なワークフロー
   - 推奨ワークフロー（ブランチ作成 → 学習記録自動生成 → 著作権チェック → PR自動作成）

**効果:**

### 3. テンプレートファイルの配置の統一

一貫性を保つため、テンプレートファイルの配置を各カテゴリディレクトリ内に統一した。

**変更内容:**
```bash
# Before
.templates/daily-diary.md

# After
Diary/日記テンプレート.md
Books/読書メモテンプレート.md
Draft/下書きテンプレート.md
```

**ポイント:**
- 各カテゴリにテンプレートが配置されることで、直感的に見つけやすくなった
- `.templates/` ディレクトリを削除し、リポジトリ構造がシンプルになった

### 4. Draft/ フォルダの新設

「きちんと整理された学び」を公開する前に、気軽にメモできる場所として `Draft/` ディレクトリを新設した。

**目的:**
- ちょっとした気づきや断片的な情報を素早くメモ
- 将来的にやりたいことのアイデアを保存
- 後で整理して Tech/Books/Diary/ に昇格させる下書きとして活用

**作成したファイル:**
- `Draft/下書きテンプレート.md` - メモ作成用のテンプレート
  - 概要、メモ・気づき、TODO、参考リンク、昇格時チェックリストを含む

**初のDraftメモ:**
- `Draft/学習用ブログサービス.md` - React/Rails 学習用のブログサービス構想
  - Minimum Value Change、Docker、MySQL、Ridgepole/rspec を利用予定
  - Gemini で要件を壁打ち中

**ポイント:**
品質を気にせず、気軽に記録できる場所ができたことで、学びのハードルが下がった。

### 5. カスタムコマンド `/create-pr` の作成

PR作成を自動化するカスタムコマンドを実装した。

**動作:**
1. 現在のブランチ名から日付を抽出
2. `Diary/YYYY/MM/YYYY-MM-DD.md` ファイルの存在確認
3. Diary ファイルから `###` で始まる見出し（トピック）を抽出
4. `gh pr create` でPRを自動作成
   - タイトル: `TIL : YYYY-MM-DD`
   - Body: トピックの箇条書きリスト

**コマンド例:**
```bash
# Claude Code 上で実行
/create-pr
```

**効果:**
手動でPRを作成する手間が省け、日々のワークフローがさらにスムーズになった。
