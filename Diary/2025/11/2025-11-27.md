# 2025-11-27の学習記録

## 今日学んだこと

### 1. Claude Codeのカスタムコマンドでプロジェクト進捗管理

MyBlogプロジェクトの進捗記録を効率化するため、`/myblog-progress` コマンドを活用しました。このコマンドは、my-blogリポジトリのコミット履歴とGitHub Projectのissue状態を自動的に取得し、進捗ファイルを生成してくれます。

**コマンド実行:**
```bash
# Claude Codeで実行
/myblog-progress
```

**自動生成される内容:**
- 前回からの新規コミットリスト（コミットハッシュとメッセージ）
- 完了したissue（Done状態で未記録のもの）
- 進行中のissue（In Progress状態）
- `.done-issues.json` による重複防止

これにより、手動でコミット履歴を確認したりissueを探す手間が省け、進捗記録作成が大幅に効率化されました。

**参考:** https://github.com/mrmrtmrn/TIL/blob/main/CLAUDE.md

### 2. プロジェクト管理ルールの整理とIssue管理への統一

MyBlogプロジェクトの進捗管理ルールを見直し、タスク管理をGitHub Issueに統一しました。

**変更内容:**
- 進捗テンプレートから「次にやること」セクションを削除
- CLAUDE.mdから「Issue作成ルール」セクションを削除
- タスクはすべてGitHub Issueで管理する方針に統一

**理由:**
Issue管理はMyBlogリポジトリ側で管理することにしたためこのリポジトリ側でProjectに対してIssueを作ることはやめた

### 3. Gitのglobal設定でアカウント情報を管理

コミット時のアカウント情報がリポジトリごとに設定されていたため、global設定に統一しました。

**設定コマンド:**
```bash
git config --global user.name "your-username"
git config --global user.email "your-email@example.com"
```

また、誤った情報でコミットしていた場合の修正方法も学びました：

```bash
# 直前のコミットのauthorを修正
git commit --amend --author="your-username <your-email@example.com>" --no-edit
```

global設定により、今後は全リポジトリで統一されたアカウント情報が自動的に使われるようになりました。

## まとめ

今日は、MyBlogプロジェクトの進捗管理を効率化するための環境整備を行いました。Claude Codeのカスタムコマンドを活用することで、コミット履歴やissue状態の取得が自動化され、手動作業が大幅に削減されました。また、プロジェクト管理ルールを整理し、MyBlogリポジトリでのGitHub Issueに統一することで、タスク管理がより明確になりました。Gitの設定も見直し、global設定でアカウント情報を一元管理できるようになりました。
