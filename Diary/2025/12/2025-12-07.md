## 今日学んだこと

### Volta/npm/pnpmの依存関係の整理

npmコマンドが使えるのは知っていたが、以前インストールしたvoltaとの関係がわからず、pnpmも導入したいと考えていたため、環境の整理を実施。

#### 調査結果

環境を確認した結果、**すべてvoltaが管理していた**ことが判明：

```bash
# バイナリの場所を確認
$ which node
/Users/$USER/.volta/tools/image/node/24.11.1/bin/node

$ which npm
/Users/$USER/.volta/tools/image/node/24.11.1/bin/npm

$ which pnpm
/Users/$USER/.volta/bin/pnpm
```

すべてvoltaが管理するディレクトリ配下に配置されていた。

#### voltaを使っている環境でのnpm install -g

voltaがインストールされている環境では、`npm install -g`で実行したグローバルインストールも**voltaの管理下に入る**。

つまり：
- 「npmでグローバルインストール」≠ voltaと別の場所
- voltaがnpmを管理しているので、`npm install -g`もvoltaの管理下に入る
- `/Users/$USER/.volta/tools/image/node/24.11.1/lib/`にパッケージが配置される

#### pnpmのメリット

1. **ディスク容量の大幅削減**: コンテンツアドレス可能ストアを使用し、1つのパッケージを1回だけディスク保存。10個のプロジェクトでReactを使用していても、ディスクに保存されるReactは1つだけ。

2. **インストール速度が速い**: パッケージの再利用により、初回インストール後は劇的に高速化。

3. **厳格な依存関係管理**: `package.json`に明示的に記載されていないパッケージは`require()`できない。幽霊依存（phantom dependencies）の問題を回避。

4. **モノレポに強い**: `pnpm workspace`機能が標準装備。複数プロジェクトを1つのリポジトリで管理する際に便利。

5. **互換性が高い**: npmと同じコマンド体系（`pnpm install`, `pnpm add`など）。

#### グローバルインストールの使い分け

| 方法 | インストール先 | バージョン管理 | 推奨度 |
|------|---------------|---------------|--------|
| `volta install` | `/Users/$USER/.volta/bin/` | ✅ voltaが管理 | 高 |
| `npm install -g` | `/Users/$USER/.volta/tools/image/node/24.11.1/lib/` | ✅ voltaが管理 | 中 |
| `pnpm install -g` | `/Users/$USER/Library/pnpm/` | ❌ pnpmが独自管理 | 低 |

`pnpm setup`を実行すると`.zshrc`にPNPM_HOMEが追加されるが、これによりpnpmのグローバルパッケージがvoltaの管理外になり、ツールのバージョン管理が分散してカオスになる。

#### 推奨される使い分け

```bash
# ✅ グローバルツール（claude, typescript, など）
volta install @anthropic-ai/claude-code
volta install typescript

# ✅ プロジェクトの依存関係（速度・容量節約のため）
cd your-project
pnpm install
pnpm add react
```

**結論**: グローバルツールはvolta、プロジェクト依存はpnpmという使い分けがベスト。

#### .zshrcからpnpmグローバル設定を削除

`pnpm setup`で追加されたグローバル設定を`.zshrc`から削除し、voltaのみで管理する方針に統一。

```bash
# 削除した設定
# pnpm
export PNPM_HOME="/Users/$USER/Library/pnpm"
case ":$PATH:" in
  *":$PNPM_HOME:"*) ;;
  *) export PATH="$PNPM_HOME:$PATH" ;;
esac
# pnpm end
```

### モノレポ（Monorepo）の概念

pnpmの説明で「モノレポに強い」という言葉の意味がわからなかったため質問。

**モノレポ（Monorepo）** = **mono**（単一） + **repository**（リポジトリ）

複数のプロジェクト/パッケージを1つのリポジトリで管理する手法。

#### 具体例

**従来のマルチレポ方式:**
```
github.com/yourname/app-frontend/     ← リポジトリ1
github.com/yourname/app-backend/      ← リポジトリ2
github.com/yourname/shared-utils/     ← リポジトリ3
```

**モノレポ方式:**
```
github.com/yourname/my-app/
├── packages/
│   ├── frontend/        ← プロジェクト1
│   ├── backend/         ← プロジェクト2
│   └── shared-utils/    ← プロジェクト3
└── package.json
```

実際の例として、Reactリポジトリ（https://github.com/facebook/react）は15個以上のパッケージを1つのリポジトリで管理している。

#### pnpmがモノレポに強い理由

1. `pnpm workspace`機能が標準装備
2. パッケージ間の依存関係を自動解決（`workspace:*`で同じモノレポ内のパッケージを参照）
3. 同じパッケージをディスクに1回だけ保存し、シンボリックリンクで共有
4. 一括操作が簡単（`pnpm -r build`ですべてのパッケージでビルド）

### Claude Codeのモデル切り替え

Claude Codeでは以下の3つのモデルが利用可能：
- **`sonnet`** - バランスの良いデフォルトモデル（現在使用中: `claude-sonnet-4-5-20250929`）
- **`opus`** - より高度な推論が必要な複雑なタスク向け（`claude-opus-4-5-20251101`）
- **`haiku`** - 軽量で高速、コスト効率的

モデルIDの末尾の数字（例: 20250929）はモデルのリリース日を示す。

### Claude Codeの更新方法

voltaでclaude-codeを更新する手順は簡単：

```bash
# 最新バージョンに更新
volta install @anthropic-ai/claude-code

# バージョン確認
claude --version  # 現在は 2.0.60
```

voltaは自動的に最新バージョンをインストールし、既存のバージョンを置き換える。
