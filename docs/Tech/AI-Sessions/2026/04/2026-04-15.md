# AI Session Notes - 2026-04-15

## モバイルアプリ開発の技術選定

### 学んだこと

- 2026年時点の新規モバイルアプリ開発では、`React Native + Expo`、`Flutter + Firebase`、`SwiftUI / Jetpack Compose` のネイティブ開発が主要な候補になる
- 最適解は「どの技術が一番優れているか」ではなく、既存の技術スタックと何を最適化したいかで変わる
- Web フロントエンドや TypeScript の知見を活かしたい場合は `React Native + Expo` の連続性が高い
- バックエンド寄りの開発経験が強く、UI を 1 コードベースで素早く作りたい場合は `Flutter + Firebase` が有力になる
- OS 機能を深く使う、最新の UI ガイドラインに厳密に合わせる、体験品質を最優先する場合はネイティブ開発が最も強い

### 詳細

技術選定は「どのアプリを作るか」が固まる前でも、判断軸だけは先に整理できる。

- `React Native + Expo`
  - JavaScript / TypeScript の知識を活かしやすい
  - Web フロントエンドや Node.js の知見と連続性が高い
  - セットアップ、実機確認、ビルド、配布の初速が出しやすい
- `Flutter + Firebase`
  - UI の再現性が高く、iOS / Android で見た目を揃えやすい
  - 認証、通知、分析、クラッシュ監視などをまとめて立ち上げやすい
  - Firebase を使いつつ、複雑な権限や整合性が必要な部分だけ自前 API に逃がす構成が現実的
- ネイティブ開発
  - カメラ、Bluetooth、AR、OS 独自機能などを深く扱う用途で強い
  - パフォーマンスや UI の自然さを最優先する場合に向く

## Expo の位置づけ

### 学んだこと

- Expo は React Native の代替ではなく、React Native 開発を楽にするための開発基盤とツール群
- 学習や試作では `Expo Go`、本格開発では `development build` を使い分ける考え方が重要
- 「Expo は本番向きではない」という認識は古く、現在は本番運用でも十分に現実的な選択肢になっている

### 詳細

Expo を使うと、初期セットアップ、実機確認、ネイティブ機能の導入、クラウドビルドなどが整理される。
そのため、React Native をこれから始める場合は、まず Expo ベースで入るのが自然なことが多い。

## 実機インストールと配布の前提

### 学んだこと

- ストア公開をしなくても、手元のスマートフォンにアプリを入れて試すことはできる
- Android は APK などを使って比較的自由に実機インストールしやすい
- iPhone は Apple の署名や配布ルールに従う必要があり、Android より制約が強い
- 自分用の実機確認と、他人に配るための配布方法は分けて考える必要がある
