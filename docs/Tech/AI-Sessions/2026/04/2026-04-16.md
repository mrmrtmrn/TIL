# AI Session Notes - 2026-04-16

## ハーネスエンジニアリングとエージェント開発基盤

### 学んだこと

- エージェント文脈でのハーネスエンジニアリングは、単なるテストハーネス作成ではなく、AI エージェントが安全かつ再現可能に作業できる環境を設計することを指す
- 重心は「人間が直接たくさんコードを書くこと」よりも、エージェントが作業しやすい制約、ツール、観測性、フィードバックループを整えることにある
- `AGENTS.md`、テスト、CI、ログ参照、ブラウザ操作、作業ディレクトリ分離などは、エージェント向けハーネスの一部として捉えられる

### 詳細

エージェントファーストの開発では、対象アプリそのものよりも先に「エージェントが迷わず動ける足場」を整える価値が高い。

その足場には次のような要素が含まれる。

- 作業ルールを短く伝えるガイド
- 再現可能なテストと確認手順
- UI やブラウザを検証するための操作手段
- ログ、メトリクス、トレースを読むための経路
- タスクごとの独立した作業場所

## Git worktree の役割

### 学んだこと

- `git worktree` は、1 つの Git リポジトリから複数の作業ディレクトリを持ち、別々のブランチやタスクを同時並行で扱うための仕組み
- エージェント運用では、タスクごとに独立した作業場所を与えることで、変更、ログ、起動状態の衝突を減らしやすい
- ただしソースコードだけ分けても不十分で、ポート、ログ出力先、一時ファイル、成果物などの副作用も worktree ごとに分離する必要がある

### 詳細

worktree は GitHub 上のリポジトリ構造を変えるものではなく、ローカルの作業ディレクトリ配置を整理するための仕組みである。

複数の worktree を安定運用するには、次のような方針が有効になる。

- すべての worktree を 1 つの親ディレクトリ配下に集約する
- 作成、初期化、削除をスクリプト化する
- `.local/` などの作業用ディレクトリへ副作用を閉じ込める
- エージェントには対象 worktree の境界を明示する

## 共有設定とローカル権限設定の分離

### 学んだこと

- worktree 運用で重要なのは、リポジトリ内で共有すべき設定と、各自のローカル環境に閉じるべき設定を分けること
- `AGENTS.md` や運用スクリプト、権限設定の雛形は Git 管理に向く
- 実際の `allow` / `deny` 設定やホームディレクトリ依存の実パスは、Git 管理せずローカル設定として持つほうが自然
- 運用テンプレートや実践サンプルは、TIL より専用のサンプルリポジトリとして分離したほうが育てやすい

### 詳細

「どこを触ってよいか」という実権限は、通常はリポジトリではなく実行環境の責務になる。
そのため、共有リポジトリには方針や雛形だけを置き、実パスを含む本番設定はローカルに置く分離が扱いやすい。

また、学びの要約と再利用可能な配布物は役割が異なるため、後者は別リポジトリへ切り出したほうがメンテナンスしやすい。
