# AI Session Notes - 2026-04-19

## Hono が伸びる背景と「ランタイム差分」の理解

### 学んだこと

- Hono は「速い」だけでなく、**Web Standards（Request/Response）ベース**かつ**複数ランタイム対応**で評価されている
- 現在の JavaScript サーバー開発は、Node.js 単体だけでなく、Cloudflare Workers・Bun・Deno などを含む前提に広がっている
- 「ランタイム」は実行環境のこと。フレームワーク（Hono）とランタイム（Node/Bun/Workers）は役割が異なる
- Hono はアプリ本体（ルーティング・ハンドラ）は共通化しやすく、差分は主に**起動方法・エントリポイント・環境依存機能**に出る
- Express と Hono は優劣というより得意領域が異なる。Express は情報量と既存資産、Hono は軽量性とランタイム横断性が強み

### 整理メモ

#### 1) Hono が「伸びている」と言える理由

- Edge/Workers 文脈と相性がよい
- Node 専用ではなく、実行環境をまたいで同じ設計感で書ける
- TypeScript で軽量に始めつつ、Validation や RPC に発展させやすい

#### 2) 「Edge / Workers 時代」の意味

- 従来の「単一リージョンのサーバー中心」から、ユーザーに近い拠点で処理する設計が増えている
- その結果、ランタイムを固定しすぎない設計（Web 標準 API ベース）が実務上の価値を持ちやすい

#### 3) ランタイムごとに何が変わるか

- 大きく変わらない: `new Hono()`、`app.get()` などのアプリ本体
- 変わる: 起動方法、エントリポイント、環境変数・プラットフォーム固有 API
  - Node.js: `@hono/node-server` の `serve(app)` で起動
  - Workers/Bun: `export default app` で渡す形が基本

### 実装イメージ（最小）

```ts
import { Hono } from 'hono'

const app = new Hono()
app.get('/', (c) => c.text('Hello'))

export default app // Workers/Bun の典型
```

```ts
import { Hono } from 'hono'
import { serve } from '@hono/node-server'

const app = new Hono()
app.get('/', (c) => c.text('Hello'))

serve(app) // Node.js の典型
```

### Express と Hono の使い分け（現時点の理解）

- **Express を選びやすいケース**
  - Node 専用で運用する
  - 既存資産・採用実績・情報量を重視する
- **Hono を選びやすいケース**
  - Workers/Bun なども視野に入る
  - 軽量で Web 標準寄りの書き味を重視する
  - TypeScript と API 契約の整理を早めに意識したい
