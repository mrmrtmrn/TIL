# AI Session Notes - 2026-04-08

## Playwrightの基礎と特徴

### 学んだこと

- PlaywrightはWebブラウザ操作を自動化するためのツールで、主にE2Eテストで活用される
- Chromium / Firefox / WebKit を統一されたAPIで操作できる
- JavaScript（Node.js）を中心に、Python / Java / C# など複数言語に対応している
- クリックや入力などのブラウザ操作をコードとして記述して実行する

### 詳細

Playwrightでは、ブラウザを起動してページを開き、要素を指定して操作する。

```javascript
const { chromium } = require('playwright');

(async () => {
  const browser = await chromium.launch();
  const page = await browser.newPage();

  await page.goto('https://example.com');
  await page.click('button#submit');

  await browser.close();
})();
```

## ブラウザエンジンの理解

### 学んだこと

- ブラウザとレンダリングエンジンは別の概念である
- レンダリングエンジンはHTML/CSS/JSを解釈し、画面表示を担う
- 主なエンジンは以下の通り
  - Chrome → Blink
  - Safari → WebKit
  - Firefox → Gecko
- WebKitはSafariやiOSブラウザで使われているエンジンである

## PlaywrightとSeleniumの違い

### 学んだこと

- Playwrightは比較的新しく、モダンな設計思想を持つ
- Seleniumは歴史が長く、実績と対応範囲が広い
- 主な違いは以下の通り
  - Playwright: 高速・セットアップが簡単・安定性が高い
  - Selenium: 対応言語やエコシステムが豊富
- Playwrightはブラウザドライバへの依存が少なく、シンプルに扱いやすい

## なぜPlaywrightが注目されているか

### 学んだこと

- モダンなAPI設計でコードを書きやすい
- マルチブラウザ対応が統一されている
- テストの安定性が高く、flakyになりにくい
- セットアップがシンプルで導入しやすい

## ブラウザ自動化の本質

### 学んだこと

- Playwright / Selenium などのツールは本質的に同じ仕組みで動く
- HTML構造（タグ・class・id）を指定して操作する
- フロントエンドの構造理解が自動化の品質に直結する

## PlaywrightとAIの相性

### 学んだこと

- AIと組み合わせることでテスト自動化の効率を高められる
- 具体例は以下の通り
  - テストケースの自動生成
  - UI変更への柔軟な対応
  - テスト結果の分析

## PlaywrightとRubyの関係

### 学んだこと

- Playwrightは公式にはRubyをサポートしていない
- Ruby環境ではSeleniumの利用が一般的である
- Playwrightを使いたい場合はNode.jsなど別言語の利用が現実的となる
