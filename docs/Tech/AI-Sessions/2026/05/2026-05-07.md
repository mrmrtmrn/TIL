# AI Session Notes - 2026-05-07

## Go の JSON decode と struct tag

### 学んだこと

- Go の struct を定義しただけでは、HTTP request の JSON が自動的に struct へ変換されるわけではない。
- JSON から struct への変換は `encoding/json` の `Decoder.Decode` などを明示的に呼び出して行う。
- struct field に付ける `` `json:"name"` `` は struct tag であり、JSON のキー名と Go の field 名を対応させる。
- response では `Encoder.Encode` などを使い、struct や map を JSON として書き出せる。
- PATCH 用の input struct では pointer field を使うと、「未送信」と「ゼロ値が明示的に送られた」を区別できる。

### 詳細

request body の JSON を入力用 struct に入れる場合、典型的には次のように decode する。

```go
type CreateInput struct {
    Title string `json:"title"`
}

var input CreateInput

decoder := json.NewDecoder(r.Body)
if err := decoder.Decode(&input); err != nil {
    // invalid JSON
}
```

`json:"title"` は、JSON 側の `"title"` と Go 側の `Title` field を対応させる指定。

PATCH のような部分更新では、pointer を使うと送信有無を判定できる。

```go
type UpdateInput struct {
    Title *string `json:"title"`
    Done  *bool   `json:"done"`
}
```

この場合、`done` が未送信なら `Done == nil`、`false` が明示的に送られたなら `Done != nil && *Done == false` と判定できる。

## Go の constructor 風関数と `&`

### 学んだこと

- Go には class の constructor 構文はないため、`NewXxx` のような関数で struct を初期化することが多い。
- `&T{...}` は `T` 型の値を作り、そのアドレスを取って `*T` として返す。
- 関数の戻り値が `*T` なら、`return &T{...}` とするのが自然。
- 呼び出し側で毎回 `&value` を取らせるより、constructor 風関数が完成した形を返すほうが使いやすい。
- method が pointer receiver なら、constructor 風関数も pointer を返すと一貫しやすい。

### 詳細

```go
type Service struct {
    repo Repository
}

func NewService(repo Repository) *Service {
    return &Service{
        repo: repo,
    }
}
```

`Service{...}` は値を作る式で、`&Service{...}` はその値へのポインタを作る式。

戻り値を値にすることもできるが、状態や依存を持つ service のような部品は、アプリ起動時に 1 つ作って共有する意図で pointer を返すことが多い。

## Go の関数型フィールド

### 学んだこと

- Go では関数も値として扱えるため、struct の field に関数を持たせられる。
- `func() time.Time` は「引数なしで `time.Time` を返す関数」という型。
- `time.Now` のような関数そのものを field に入れておくと、呼び出し時に `s.now()` のように実行できる。
- 現在時刻を直接呼ばず関数 field にしておくと、テストで固定時刻を返す関数に差し替えやすい。

### 詳細

```go
type Service struct {
    now func() time.Time
}

func NewService() *Service {
    return &Service{
        now: time.Now,
    }
}
```

`now: time.Now` は関数そのものを代入している。`time.Now()` と書くと、その瞬間の時刻値を取得する呼び出しになる。

引数ありの関数型は次のように書ける。

```go
validator func(string) bool
finder    func(context.Context, int64) (Item, error)
```

## Go の複数戻り値と error

### 学んだこと

- Go では `(Value, error)` のように、結果と error を複数戻り値で返すのが一般的。
- 関数定義で `(Todo, error)` のように宣言した場合、`return` でも `Todo` と `error` の 2 つを返す。
- エラー時は `Todo{}` のようなゼロ値と、具体的な error を返すことが多い。
- 呼び出し側は `result, err := fn()` のように受け取り、`err != nil` の場合は result を使わず error 処理に進む。

### 詳細

```go
func Find(id int64) (Item, error) {
    if id <= 0 {
        return Item{}, ErrInvalidID
    }

    return Item{ID: id}, nil
}
```

呼び出し側はすぐに error を確認する。

```go
item, err := Find(id)
if err != nil {
    return err
}

// err が nil なので item を使う
```

## Go の `range` は index と要素のコピーを返す

### 学んだこと

- slice に対する `for i, item := range items` では、`i` に index、`item` にその要素の値が入る。
- `:=` は短い変数宣言で、型推論付きで新しい変数を作る。
- `range` で受け取った `item` は基本的に要素のコピーなので、`item` を書き換えても元の slice 要素は更新されない。
- slice の中身を置き換える場合は、`items[i] = newValue` のように index を使って代入する。

### 詳細

```go
for i, item := range items {
    if item.ID == updated.ID {
        items[i] = updated
        return updated, nil
    }
}
```

この形は、今見ている要素の ID を確認し、一致した index の要素を新しい値で丸ごと置き換える処理として読める。

index が不要な場合は `_` で捨てられる。

```go
for _, item := range items {
    // item だけ使う
}
```
