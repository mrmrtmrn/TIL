# AI Session Notes - 2026-05-06

## Go の package は同じディレクトリ内の複数ファイルで構成できる

### 学んだこと

- Go では同じディレクトリにあり、同じ `package` 名を宣言している `.go` ファイル群が、ビルド時に 1 つの package として扱われる。
- 同じ package 内で定義された型、関数、変数は、ファイルが違っても import なしで参照できる。
- import にない裸の名前が出てきた場合、まず同じ package 内の別ファイルに定義がある可能性を考える。
- package が大きくなりすぎると名前の出どころを追いづらくなるため、Go では「大きすぎず細かすぎない package」に保つことが大事になる。

### 詳細

同じ package 内では、ファイル分割は整理のための単位であり、名前空間は package 単位になる。

```go
// errors.go
package item

var ErrNotFound = errors.New("not found")
```

```go
// repository.go
package item

func FindByID(id int64) (Item, error) {
    return Item{}, ErrNotFound
}
```

この場合、`ErrNotFound` は同じ package の名前なので `item.ErrNotFound` のように書かず、そのまま参照できる。

## Go の struct と method は class の代わりのように使われる

### 学んだこと

- Go には `class` キーワードや継承はない。
- 状態を持つ型は `struct` で定義し、その型に receiver 付きの関数を定義することで method を生やす。
- `struct + method` は、class に慣れている人にとっては「class 的なもの」として理解できる。
- `func (r *Repository) FindByID(...) ...` のような宣言では、`(r *Repository)` が receiver であり、この method をどの型に紐づけるかを表している。

### 詳細

Go の method 宣言は、通常の関数に receiver が追加された形として読める。

```go
func (r *Repository) FindByID(id int64) (Item, error) {
    // ...
}
```

分解すると次のようになる。

```text
func              関数または method の定義
(r *Repository)   receiver
FindByID          method 名
(id int64)        引数
(Item, error)     戻り値
```

class 構文ではないが、呼び出し側からは次のように method として使える。

```go
repo.FindByID(1)
```

## Go の pointer receiver は実体へのポインタを受け取る

### 学んだこと

- `*Repository` は `Repository` 型の値そのものではなく、その値へのポインタを表す。
- `func (r *Repository) ...` は、method の receiver として `Repository` の実体へのポインタを受け取るという意味。
- Go は厳密には「参照渡し」ではなく、ポインタ値を渡している。
- pointer receiver にすると、method 内で元の struct の状態を更新できる。
- `sync.Mutex` や `sync.RWMutex` のようなロックを含む struct はコピーすると危険なので、pointer receiver を使うのが自然。

### 詳細

`*` は型の位置では「その型へのポインタ」を表す。

```go
var repo *Repository
```

一方で `&` は値のアドレスを取る。

```go
repo := &Repository{}
```

constructor 風の関数では、struct を作ってそのポインタを返す形がよく使われる。

```go
func NewRepository() *Repository {
    return &Repository{}
}
```

このようにして作った値に対して pointer receiver の method を呼ぶと、method 内では同じ repository の状態を参照・更新できる。

## sync.RWMutex の RLock は読み取り用ロック

### 学んだこと

- `r.mu.RLock()` の `RLock` は、repository 自体の method ではなく、repository が持つ `mu` フィールドの method。
- `mu` が `sync.RWMutex` 型であれば、`RLock` や `RUnlock` は標準ライブラリの `sync.RWMutex` に定義された method。
- `RLock` は読み取り用ロックで、読み取り同士は並行しやすく、書き込みとは競合しないようにする。
- `defer r.mu.RUnlock()` と書くことで、関数終了時に読み取りロックを解除できる。

### 詳細

メモリ上の slice や map を複数 goroutine から読む・書く可能性がある場合、ロックで保護する必要がある。

```go
func (r *Repository) FindByID(id int64) (Item, error) {
    r.mu.RLock()
    defer r.mu.RUnlock()

    // 読み取り処理
}
```

読むだけの処理では `RLock` / `RUnlock`、書き換える処理では `Lock` / `Unlock` を使うことで、並行アクセスによる不整合を避けやすくなる。
