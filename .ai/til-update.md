# til-update

このリポジトリで AI セッション由来の学びを記録する際の正本手順。
`til-update` は、会話から抽出した**汎用的な技術知識**を `docs/Tech/AI-Sessions/` に記録するためのワークフローを指す。

## 目的

- セッションから再利用可能な技術知識を抽出して蓄積する
- プロジェクト固有のやり取りではなく、他の場面でも役立つ学びだけを残す
- 1 日単位のノートとして自然に統合し、日報のような時系列ログにはしない

## 使い方

- `til-update` - セッションから学びを抽出し、当日ファイルを作成または更新してコミットする
- `til-update push` - 上記に加えて `main` へプッシュする

## 定数

重要: 日付は必ずシェルで `date` を実行して取得すること。セッションのシステムコンテキストに含まれる日付は使用しない。

```bash
YEAR=$(date +%Y)
MONTH=$(date +%m)
TODAY=$(date +%Y-%m-%d)
TARGET_DIR=docs/Tech/AI-Sessions/$YEAR/$MONTH
TARGET_FILE=$TARGET_DIR/$TODAY.md
```

## 抽出ルール

会話全体を振り返り、以下の観点で汎用的な学びを抽出する。

- 新しく学んだ技術知識・概念
- 問題解決のアプローチ・パターン
- ツールやコマンドの使い方・Tips
- 設計やアーキテクチャの知見
- デバッグ手法や落とし穴・ハマりポイント
- ベストプラクティスやアンチパターン

次のルールを厳守する。

- ユーザー主導の学びのみ対象にする
- AI が自律的に発見した修正や調査結果は含めない
- プロジェクト固有のコード・設定・ファイルパスは含めない
- 固有名詞は一般化し、技術トピックとして独立して意味が通る形にする
- 学びがない場合は無理に作らず、その旨を簡潔に報告して終了する

### 例

- OK: ユーザーの質問を起点に `ctx.Done()` の使い方を学んだ
- OK: ユーザーの相談を起点に Docker レイヤー順序の最適化を学んだ
- NG: AI がビルドエラーを見つけて勝手に依存バージョンを直した
- NG: AI がテスト失敗を起点に自律的にモックを修正した

## 出力先

```bash
mkdir -p "$TARGET_DIR"
```

`$TARGET_FILE` を確認し、以下のどちらかで処理する。

### 新規作成

```markdown
# AI Session Notes - YYYY-MM-DD

## [トピックのタイトル]

### 学んだこと

- 箇条書きで汎用的な学びを記載

### 詳細

必要に応じてコード例や詳しい説明を記載する。
不要であればこのセクションは省略可。

## 参考リンク

- [記事タイトル](URL) - セッション中に参照したブログ記事やドキュメント

## メタ情報

- **ツール**: Claude Code / Gemini CLI / Codex など使用したツール名
- **関連技術**: Go, React, Docker など関連する技術タグ
```

### 既存ファイルの更新

既存の当日ファイルがある場合は、新しい学びを 1 つの文書として自然に統合する。

- 既存トピックと重なる内容は同じセクションに統合する
- 新しいトピックは文書の流れに沿って追加する
- セッションごとの区切りは入れず、1 日分のノートとして整理する
- メタ情報には新しいツール名や技術タグを追記する
- 参照した外部リソースがあれば「参考リンク」に追記する

## コミット

変更が発生したら、以下の形式でコミットする。

```bash
git add docs/Tech/AI-Sessions/
git commit -m "feat: 学びのサマリ（30文字程度）

- トピック1のタイトル
- トピック2のタイトル
- ..."
```

コミットメッセージのルール:

- 1 行目は `feat: ` に続けて内容の要約を書く
- 日付はコミットメタデータに残るため件名には含めない
- 3 行目以降に今回追記・新規作成したトピック名を箇条書きで書く

## push モード

`til-update push` の意図で依頼された場合のみ、コミット後に以下を実行する。

```bash
git push
```

## 完了報告

最後に、追記または更新した学びの要点を簡潔に報告する。
